# Word 成稿与图文交付

## 唯一交付文件

默认一份“论文简称-读书笔记.docx”，读书笔记即公众号发布稿。用户明确要求其他格式时遵循。制作文档的代码、提取文本、图片文件和核验记录都是内部工具或临时资源，不作为笔记交付，不同时附 Markdown、PDF 或多个版本。

使用当前环境可用的文档能力。采用真实标题层级和连贯段落，标题为黑色，清除模板默认的彩色横线或装饰边框；少量加粗，不把正文写成标签清单。不加入研读版本、覆盖清单、来源操作说明或文末参考来源栏目；保留开头的原文信息与必要就近引用。不生成 Word／Markdown 表格、公式对象或数学符号表达式。

## 选取原文图表

- 先决定图片要支持的研究发现。优先选择核心比较、识别检验、关键机制或方法结构；不为装饰、凑数量或替代分析插图，没有固定图片配额。
- 从目标论文 PDF 渲染或直接截取原图、原表。不要自行重新排表、改绘数据图、让生成式图像复刻证据或截取二手文章替代原文。原表截图是允许的图像证据，不受自制表格禁项影响。
- 裁去无关页边和页眉，保留理解所需的列名、图例、坐标、单位、组别、期限、注释和统计口径。必要时分成连续面板并说明对应关系；不能只留下显著行、截掉不利结果或失去比较对象。
- 原图表包含的符号可保留。不把正文公式截成图片来绕过公式限制。不去除来源或版权标记，不假称已取得授权。
- 按文档可用宽度插入清晰截图，保持纵横比，避免整页缩成无法阅读的小图。长表按有意义的面板切分，必要条件与注释仍须可见；无法清晰呈现时改用精练文字分析，不强行插图。

## 解读与排版

图片放在讨论对应证据的位置，图注用“原文表3：内部人交易的数量与金额”等简短形式，保留原编号。非连续截取不得让读者误以为是完整原表。正文中的“表3”仍指原论文表3，不另起编号造成混淆。

解读围绕研究发现和经济含义：该比较回答什么问题，结果改变或支持何种判断，重要条件和反向证据是什么。只在量级、基准或差异影响判断时引用数字。不得逐行逐列报数、把系数与显著性写成清单，或用“表中可见”代替解释。不能把不显著写成没有效应，也不能把一组显著另一组不显著写成组间差异显著。

文档图片必须内嵌，不能依赖外链或临时目录。保存后渲染并逐页查看，检查图片文字、图注位置、段落衔接、分页、孤立标题及异常空白。图片需要实际查看，不能只核对插入成功或像素尺寸。渲染失败时尝试当前环境的其他办法；确实无法检查时如实说明，不声称已通过视觉验收。

Python 可用时运行 `python scripts/validate_note.py <成稿.docx>`，排查格式禁项、残留 Markdown 及图片引用。它不判断内容深度、读数准确性或视觉清晰度，不能替代原文核验和逐页查看。

## 发布与清理

“可供发布”只要求交付稿件。实际代发或保存平台草稿沿用会话中明确的账号、内容和目的地授权；平台限制按当前界面或官方说明核对。按实际状态报告本地成稿、草稿、提交审核或正式发布。

文件保存并检查成功后，核对本任务临时路径，再删除不再需要的提取文本、截图、代码、缓存、渲染页和试跑文件。不得清理用户输入、技能源码或其他任务成果。最终回复以唯一 Word 文件链接为主，不附独立核验报告。
